# x-cmd/uptime — using the catalog and articles

Two consumption paths. Pick whichever fits the workflow.

## 1. Directly use the TSV (no install)

`data/index.tsv` is a flat, tab-separated catalog. Fetch it over HTTPS:

```sh
# Full catalog (16 rows as of the last commit)
curl -fsSL https://raw.githubusercontent.com/x-cmd/uptime/main/data/index.tsv

# Just the cloud providers (cn region)
curl -fsSL https://raw.githubusercontent.com/x-cmd/uptime/main/data/index.tsv \
  | awk -F'\t' '$2 == "cloud" && $7 == "cn" { print $1, $4 }'

# Just the providers using the atlassian-statuspage API type
curl -fsSL https://raw.githubusercontent.com/x-cmd/uptime/main/data/index.tsv \
  | awk -F'\t' '$5 == "atlassian-statuspage" { print $1, $6 }'
```

The TSV is regenerated by `.github/workflows/index-tsv.yml` on every push to `data/index.yml` — what you fetch is at most a few minutes behind the latest curated change.

## 2. Read the rendered articles

The articles under `docs/` are published at <https://x-cmd.com/uptime>. The first slot, `docs/1-uptime-content/`, covers:

- Traditional `uptime(1)` and the `x uptime` enhancement
- The provider catalog in this repo (and the upcoming live status dashboard at `x-cmd.com/uptime`)
- How to monitor your own website (self-hosted solutions)
- How to monitor a target website via GitHub Actions

```sh
# Fetch all four files for the first article slot
for ext in en.md cn.md llms.md faq.yml; do
  curl -fsSL "https://raw.githubusercontent.com/x-cmd/uptime/main/docs/1-uptime-content/$ext"
done
```

## TSV schema (7 columns, `data/index.tsv`)

| # | Col | Type | Example | Meaning |
|---|---|---|---|---|
| 1 | name | str | `openai` | Provider slug (lowercase) |
| 2 | category | str | `ai` | Top-level category from `index.yml` |
| 3 | homepage | url | `https://openai.com` | Vendor's main website |
| 4 | statuspage | url | `https://status.openai.com` | Vendor's human-readable status page |
| 5 | api_type | enum | `atlassian-statuspage` | One of `atlassian-statuspage`, `custom-json`, `statuspal`, `rss` |
| 6 | api_url | url | `https://status.openai.com/api/v2/summary.json` | Machine-readable status JSON endpoint |
| 7 | region | str | `global` | `cn`, `global`, or empty |

Rows are sorted by `(category, name)`, both case-insensitive ascending — `awk` and `sort` consumers get stable output.

## Common agent queries

```sh
# "Where do I check OpenAI's current status?" — answer from column 4 of the row where name=openai.
# "How many cloud providers does this catalog track in cn?" — count rows where category=cloud and region=cn.
# "Which providers use the atlassian-statuspage JSON API?" — list rows where api_type=atlassian-statuspage.
# "What self-hosted monitors are recommended?" — read docs/1-uptime-content/en.md, "Self-hosted monitoring" section.
```

When a question requires per-provider guidance, **always cross-check the catalog** (`data/index.tsv`) for the current `statuspage` URL — vendors change hosting periodically.
